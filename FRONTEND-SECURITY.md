# Frontend security notes

## Content Security Policy

The current and proposed policy is:

```text
default-src 'self'; img-src 'self' data: blob: https://api.open-meteo.com https://geocoding-api.open-meteo.com; connect-src 'self' https://api.open-meteo.com https://geocoding-api.open-meteo.com; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'
```

`script-src 'unsafe-inline'` is still required: the legacy interface and its generated screen templates contain inline event-handler attributes (`onclick`, `onsubmit`, `onchange`, and others). A source scan found 635 handler-attribute-like occurrences across frontend JavaScript plus 5 in `index.html` (640 source occurrences total, not a runtime DOM count). Browsers block those handlers if `unsafe-inline` is removed. Removing the directive without migrating the handlers to event listeners would break navigation, forms, and screen actions. Migrate them incrementally, starting with handlers that carry dynamic data, then remove the directive after browser-flow coverage passes.

`style-src 'unsafe-inline'` remains for existing inline style attributes and dynamically assigned styles. This hardening does not change either directive; tightening them requires a separate UI migration.

The policy otherwise keeps scripts, styles, and connections same-origin except for the two Open-Meteo endpoints. Inline SVG favicon and generated canvas PNG previews explain the `data:` image allowance; quote-draft preview sources are limited to same-origin blob URLs or canvas-compatible base64 PNG data URLs.

## Local test authentication

`scripts/local.mjs` refuses to start when `NODE_ENV`, `RUNTIME_ENV`, or `SOCLE_RUNTIME_ENV` is `production`. Its simulated identities and `__local-test/*` endpoints exist only in this local development server. The server discards browser-supplied identity ID and email headers and sets identity headers only from a valid server-side local session. The session token is stored as a hash and returned only in an `HttpOnly; SameSite=Strict` cookie; the local HTTP server does not set `Secure`, which would prevent the cookie from being sent over its HTTP origin.

## Browser storage and document URLs

Browser storage is limited to the active organization selector, a session-user marker used to reset that selector, and personal weather preferences. Organization and permission authorization remains server-side. Session cookies are not read by frontend JavaScript, and frontend code does not persist authentication tokens or passwords.

Private document preview and download use same-origin `/api/documents/...` paths and remain subject to server authorization. The URL guard rejects non-HTTP(S), external origins, credentials, query strings, and fragments. Quote-draft previews accept only same-origin blob URLs or base64-encoded PNG data URLs; sketches generated by the canvas remain PNG.
